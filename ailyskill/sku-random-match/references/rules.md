# 随机款SKU匹配 — 完整业务规则

## 背景

店铺售卖的「随机款」商品用形如 `twh-1p-xxx` 的SKU下单，出单后需要确定实际发哪个SKU。
实际可发的SKU维护在多维表格的前缀子表里（含库存数量和仓库），由脚本随机抽取。

## SKU 命名

- 随机款SKU形如 `twh-1p-xxx`、`twh-2p-abc`：
  - `-Np-` 段表示抽取次数：`1p` 抽1次，`2p` 抽2次，以此类推
  - 没有 `Np` 段时默认抽 1 次
  - `Np` 前面的部分（如 `twh`、`twh-1p`）决定去哪个子表抽
- 示例：`twh-1p-01` → 在 `twh` 表抽1个；`twh-2p-02` → 抽2个

## 表格结构

多维表格里只有两类表：**订单详情表**（一张）+ **前缀表们**（若干张）。

### 订单详情表（输入+输出，含「随机款SKU」字段的表，脚本自动识别）

| 字段 | 类型 | 说明 |
|------|------|------|
| 随机款SKU | 文本 | 每天从订单导出粘贴进来的待匹配SKU |
| 订单号 | 文本 | 可选，便于追溯 |
| 仓库 | 单选 | 美东 / 东2 / 美西 / 美中 |
| 实际发货SKU | 文本 | 匹配结果，如 `AAA×2, BBB×1` |
| 状态 | 单选 | 已匹配 / 缺货 / 失败 |
| 备注 | 文本 | 失败原因或「缺X个」 |
| 匹配时间 | 日期 | 写回时间 |

### 前缀表们（库存池，手动添加，表名=前缀）

| 字段 | 类型 | 说明 |
|------|------|------|
| 实际SKU | 文本 | 真实可发货的SKU |
| 仓库 | 单选 | 同订单详情表选项 |
| 数量 | 数字 | 库存数量，由人工维护；抽中后脚本自动-1 |

新前缀只需新建一张同名表（如 `twh`、`RS1`、`twh-2p`），脚本自动识别，无需改代码。
前缀表名与SKU前缀匹配**忽略大小写**（表 `RS1` 能匹配 `rs1-3p-x`）。

## 匹配流程（每条待匹配行）

1. 解析抽取次数 N（`-Np-` 段，默认1）。
2. 找前缀表：除订单详情表外的所有表中，名字能作为该SKU开头前缀（SKU 以 表名+"-" 开头，**忽略大小写**）且名字最长的表。
   例：表 `twh` 和 `twh-1p` 同时存在时，`twh-1p-xxx` 匹配 `twh-1p`；表 `RS1` 匹配 `rs1-3p-x`。
3. 找不到 → 状态「失败」，备注「未找到前缀表」。
4. 合格池 = 该前缀表中「仓库 = 订单仓库」且「数量 ≥ 10」的行。
5. 随机抽 N 次（可重复抽同一SKU）：每次等概率抽池中一行，该行数量-1；
   数量降到 10 以下（即 9）的行移出池。
6. 抽满 N 次 → 实际发货SKU = 压缩清单（同一SKU多次用 ×N 表示，如 `AAA×2, BBB×1`），状态「已匹配」。
7. 抽不满 → 已抽到的照写，状态「缺货」，备注「缺X个」（X = 差的数量）。
8. 前缀表被抽过的行数量写回（只扣不补；补货由人工改数量）。

## 边界与约定

- 只处理「有随机款SKU 且 状态为空」的行；跑完一遍不会重复处理。
- 数量 < 10 的行永不参与抽取（保护缓冲库存，防止发超）。
- 同一轮里前面的订单先扣数量，后面的订单按扣减后的剩余数量抽（行按表格顺序串行处理）。
- 随机性：每次运行结果不同；同一订单已写回后再次运行不会重抽。
- `--dry-run` 模式只预览，不写任何数据，用于「先看看会怎么抽」。

## 常见问题

- **提示缺少配置**：config.json 没填或没复制。参照 config.example.json 填写。
- **飞书API错误 code=99991672 / permission**：应用未开通对应 base scope，去飞书开发者后台「权限管理」开通（需 base:table:read、base:record:read、base:record:update）。
- **提示 not_found / 无权限访问多维表格**：应用没被加为多维表格协作者，去多维表格「分享」里把应用加为可编辑。
- **SKU前缀找不到表**：前缀表还没建，或表名与SKU前缀不一致（大小写不敏感，但注意连字符和多余空格）。
