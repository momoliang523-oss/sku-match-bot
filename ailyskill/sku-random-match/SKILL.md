# 随机款SKU匹配

把多维表格「匹配表」中待匹配的随机款SKU，按前缀匹配同名子表、按仓库筛选、随机抽取实际发货SKU并写回。

## 何时使用

用户的消息里出现「匹配」「随机款」「抽SKU」「发货SKU」等，且目标是处理多维表格里的随机款SKU时触发。若用户只是问规则、改配置，先用参考资料回答。

## 前置条件（首次使用前确认）

1. 技能根目录有 `config.json`（从 `config.example.json` 复制），填好：
   - `appId` / `appSecret`：飞书自建应用凭据（该应用需开通 base:table:read、base:record:read、base:record:update 权限，并被加为目标多维表格的协作者/可编辑）
   - `baseToken`：目标多维表格 token（或运行时用环境变量 FEISHU_APP_ID / FEISHU_APP_SECRET / BASE_TOKEN / 命令行 --base-token 覆盖）
   - `orderTable`（可选）：订单详情表名；不填则自动识别
2. 多维表格里有两类表：
   - **订单详情表**（一张，含「随机款SKU」字段，脚本自动识别，表名无所谓）：随机款SKU｜订单号｜仓库｜实际发货SKU｜状态(已匹配/缺货/失败)｜备注｜匹配时间。每天把出单的待匹配随机款SKU（含单号、仓库）粘贴进来。
   - **前缀表们**（手动添加，表名=前缀，如 `twh`、`RS1`、`twh-1p`）：实际SKU｜仓库｜数量。库存和数量由用户随时手动维护。
3. 运行环境需 Node.js ≥ 18（脚本零依赖，仅用内置 fetch/fs/path）。

## 执行步骤

1. 在技能根目录执行 `node scripts/match.js`（无需参数）。
2. 脚本会：
   - 自动定位订单详情表（含「随机款SKU」字段的表）；
   - 扫描其中「有随机款SKU且状态为空」的行；
   - 对每行：按SKU前缀找同名前缀表（**大小写不敏感**，最长表名优先）→ 按仓库筛选、数量≥10 → 随机抽取、扣减子表数量 → 写回匹配结果与状态；
   - 输出处理摘要（已匹配/缺货/失败清单）。
3. 把脚本输出的摘要原文或稍作整理后回复用户；如果脚本报错（如缺配置、缺权限），把错误原因用一句话解释给用户并给出解决办法，不要编造结果。

## 可选参数

- `node scripts/match.js --dry-run`：只预览匹配计划，不写任何数据。用户说「先看下会抽成什么样」「预览」时使用。
- `--base-token <token>` / `--app-id <id>` / `--app-secret <s>`：临时覆盖配置。

## 业务规则（详见 references/rules.md）

- 抽取次数来自SKU里的 `-Np-` 段（`twh-2p-xxx` 抽2次）；没有 Np 默认 1 次。
- 前缀→前缀表：表名能作为SKU开头前缀（以 表名+"-" 开头，**忽略大小写**）中最长的那个表；找不到 → 状态「失败」。
- 合格池：前缀表里仓库一致 且 数量 ≥ 10；抽中一次数量-1；数量降到 10 以下移出池。
- 抽不满 N 次：已抽到的照写，状态「缺货」，备注「缺X个」。
- 已处理过的行（状态非空）不会被重复匹配。

## 回复用户时的注意

- 结果以「已匹配 X 行 / 缺货 X 行 / 失败 X 行」开头，逐行列出 `SKU → 实际发货SKU`。
- 缺货和失败要明确提示用户去补充子表库存或检查前缀表。
